# 反馈驱动的数据筛选与智能体自改进

> 当前架构说明 · 2026-10-26
>
> 本文整理目前讨论形成的设计。梯度影响估计是对学习收益的预测，不等于已经验证模型能力提升；文中的比例、区间和数据量均为演示值。

## 1. 一句话说明

**内层固定模型，由三个 Agent 反复修改、执行和评价数据筛选程序；外层使用选定数据进行 SFT，通过分技能任务测评决定接受或拒绝更新。**

内层不为每个候选策略训练一个模型，而是利用同一 checkpoint 下的样本梯度与能力目标梯度估计数据价值，并通过缓存复用控制计算成本。

Coding 与 General 是两个独立应用场景，分别维护数据、技能、开发验证任务和训练实验，不混合训练。

## 2. 整体流程

### 2.1 内层：修改筛选策略

1. **Lopt** 根据当前能力报告和历史记录，提出由 operator 组成的筛选程序。
2. **Lexec** 执行程序，得到候选子集；查询梯度缓存，仅计算尚未缓存的样本梯度。
3. **Leval** 将样本梯度与分技能能力目标梯度进行比较，汇总数据价值、覆盖、重复与成本。
4. Leval 将报告交给 Lopt，Lopt 继续修改算子选择、参数、顺序、分支和配额。
5. 连续若干次没有足够改善，或搜索预算耗尽后，停止搜索，返回历史估计最好的可行策略及其对应子集。

**整个内循环使用同一个冻结 checkpoint，计算梯度但不更新权重。**

### 2.2 外层：训练并检验实际收益

1. 从当前已接受模型创建候选训练分支。
2. 用内层最终选定的数据做固定预算的 LoRA SFT。
3. 在按技能划分的开发验证集上自由执行任务，比较目标能力、保持能力与执行成本。
4. **接受**：提交候选模型参数，更新共享模型，并建立新 checkpoint 对应的能力目标梯度。
5. **拒绝**：不更新已接受模型，继续保留旧模型及其有效缓存。
6. 无论接受还是拒绝，都保存预测、实测结果和决定原因，反馈给下一次策略搜索。

拒绝不等于永久认定全部入选数据无效。应保留失败批次和适用条件，决定暂缓组合、调整策略或补充证据。

## 3. 模型与三个 Agent

### 3.1 同一个模型，三个工作角色

记当前已接受模型为 M_t。内循环中的 Lopt、Lexec、Leval 使用同一套 M_t 权重，但具有独立上下文和角色记忆。

| 角色 | 核心职责 | 输入 | 输出 |
| --- | --- | --- | --- |
| Lopt：策略修改 | 组织和修订筛选程序 | 当前能力、候选池摘要、评价报告、历史策略 | 下一版可执行程序及修改理由 |
| Lexec：执行筛选 | 执行 operator、筛出数据、组织梯度计算 | 策略、轨迹标签、当前 checkpoint、缓存 | 候选子集、样本梯度特征、执行记录 |
| Leval：价值估计 | 比较梯度、汇总分技能价值与批次约束 | 候选子集、样本梯度、能力目标梯度 | 价值报告、风险与反馈总结 |

这些角色组织工具工作；大规模筛选、统计、前向、反向和训练由确定性代码完成，不要求 LLM 逐条阅读所有候选数据。

### 3.2 各自的记忆

| 记忆 | 保存内容 |
| --- | --- |
| 策略记忆 | 程序版本、修改位置、预期效果、有效和无效的组合 |
| 执行记忆 | 实际入选 ID、执行错误、分布变化、梯度缓存索引、成本 |
| 评价记忆 | 分技能价值估计、真实训练结果、预测偏差、接受或拒绝原因 |

记忆应保存为可追溯记录，按需检索进入上下文，不必把全部历史塞进提示词。

接受新模型后，三个角色切换到新权重，历史记忆继续保留。但任务 SFT 是否同时改善了策略设计和评价能力，需要另做实验，不能仅凭共享权重就认定成立。

## 4. 数据端：轨迹与标签

候选池由已有任务轨迹组成，当前阶段不通过 operator 改写、生成或扩增样本。

| 信息层 | 主要内容 | 用途 |
| --- | --- | --- |
| 质量与可靠性 | 结果验证、结构完整性、协议有效性、泄漏检查及证据来源 | 固定质量准入 |
| 任务与技能 | 任务类型、技能标签、技能证据位置、证据质量 | 技能筛选与分支组织 |
| 模型相关指标 | 指定 checkpoint 下的 NLL、entropy、梯度特征和影响分数 | 难度筛选与价值估计 |
| 长度与成本 | assistant 轮数、工具调用数、监督 token、上下文长度 | 长度筛选与预算控制 |
| 重复与来源 | 重复组、语义相似度、仓库、数据来源 | 去重与覆盖控制 |
| 使用状态 | 是否参与过候选训练、是否进入已接受模型的训练历史 | 避免重复与记录尝试 |

质量状态应区分 pass / fail / unknown，并记录检查来源。Teacher 的判断不能代替真正的执行验证。

前向和梯度评分不等于用于参数更新。候选训练被拒绝后，也应保留其尝试记录。数据池不要求最终全部使用。

## 5. 筛选策略：由 operator 组成的程序

### 5.1 Agent 可以修改什么

策略包含算子、参数、连接顺序、分支与合并关系。Lopt 可以：

- 新增或删除算子；
- 调整算子顺序；
- 修改阈值、偏好区间、保留比例；
- 为不同技能建立不同分支；
- 修改分支预算配比和抽样方式。

算子的代码实现、指标定义、固定质量门槛和评价标准由系统维护，不能由 Lopt 为提高估值而自行改写。

### 5.2 第一版算子库

| Operator | 作用 | 主要超参数 |
| --- | --- | --- |
| SkillSelect | 按技能筛选或建立分支 | 技能集合、任一/全部匹配 |
| EvidenceSelect | 要求目标技能被充分、可靠地展示 | 技能、证据占比、证据密度、最少证据量、完整事件条件 |
| NLLSelect | 按当前模型的学习难度筛选或截取 | 全轨迹/技能片段、原始值/百分位、偏好区间、保留比例 |
| EntropySelect | 按预测不确定性筛选或截取 | 统计范围、偏好区间、保留比例 |
| LengthSelect | 控制轨迹长度与成本 | 轮数、调用数、监督 token、上下文长度范围 |
| DedupSelect | 排除重复或近重复数据 | 重复定义、相似度阈值、代表样本规则 |
| SampleSelect | 从当前集合抽取指定规模 | 随机/排序/分层、目标规模、随机种子 |
| MixAllocate | 合并分支并分配训练预算 | 分支比例、比例单位、重叠归属、缺额处理 |

另外固定执行 QualityGate 和 BudgetPack，分别保证质量门槛与最终预算、唯一 ID 等约束。

过程相关条件先并入 EvidenceSelect，例如“存在依据反馈的有效修正”“最后一次修改后执行了测试”，暂不单独增加 ProcessSelect。

### 5.3 证据相关指标

EvidenceSelect 内部统一处理以下条件，不拆成许多小算子：

| 指标 | 含义 |
| --- | --- |
| 技能证据占比 | 目标技能证据在全部已标注技能证据中的比例 |
| 技能证据密度 | 目标技能证据在全部 assistant 监督 token 中的比例 |
| 证据充分程度 | 证据 token 数、完整技能事件数等绝对量 |
| 行为证据条件 | 是否确实展示了修正、验证等行为，而非仅声称做过 |

按 token 统计时，证据位置与 assistant 监督掩码取交集；全部技能证据的分母按位置并集统计，避免重复相加。重叠片段可以支持多个技能，因此各技能占比之和不必等于 100%。没有可用标注时，标记缺失，不能当成可靠的零值。

证据密度用于筛选整条轨迹，不意味着自动裁剪轨迹或对技能 token 加权训练。标注比例高也不能直接证明训练收益高。

### 5.4 一个组合示例

下面仅演示组合形式，参数均可修改：

```text
通过质量准入的候选池
├─ 分支 A
│  SkillSelect：失败恢复
│  → EvidenceSelect：恢复证据占比至少 50%，存在完整修正事件
│  → NLLSelect：偏好中间难度区间
│  → DedupSelect：去除近重复
└─ 分支 B
   SkillSelect：回归检查
   → EvidenceSelect：最后一次修改后有可追溯测试
   → LengthSelect：限制监督 token 范围

MixAllocate：A 分支 60%，B 分支 40%
→ BudgetPack：生成预算内的候选训练批次
```

比例先按分支分配的监督 token 计算。同一多技能轨迹可以符合多个分支，但最终只选一次、只向一个分支计账，同时另行统计它实际携带的全部技能证据。

固定阈值过滤往往只是求交集，交换顺序不改变结果；排序截断、抽样、贪心去重和集合合并才可能产生顺序效应。这里的算子顺序决定选哪些数据，不自动代表 SFT 的训练顺序。

条件过严、无法满足配额时，由执行器报告缺口，交给 Lopt 修订；不能静默放宽质量门槛。

## 6. 开发验证集与能力目标梯度

### 6.1 一套按技能划分的开发验证集

当前设计使用同一套开发验证集，承担两个用途：

1. 提供内层的分技能能力报告和奖励相关梯度。
2. 在外层 SFT 后比较新旧模型，支持接受或拒绝决定。

例如，可划分失败恢复、回归保持、工具选择等任务组。模型在环境中自由执行，由测试程序或预设评分规则产生奖励；若使用模型评价，也需要记录其来源和不确定性。

这是主动用于优化的开发集，不再称为独立验收集。另保留不参与策略修改和更新决定的最终测试集。技能分组描述任务的目标要求，不只依据执行轨迹是否恰好出现了某个行为。

### 6.2 两类梯度的来源

| 梯度 | 数据来源 | 计算方式 |
| --- | --- | --- |
| 样本梯度 | 筛选后的候选参考轨迹 | 教师强制前向，基于 SFT loss 反向 |
| 能力目标梯度 | 开发验证任务上的模型自由执行轨迹 | 获得奖励后，计算奖励相关的 policy gradient |

**两侧必须对应同一个 checkpoint 和兼容的参数表示。** 候选数据侧不需要为了计算梯度重新自由执行环境，也不执行参数更新。

能力目标梯度不能简单替换成参考答案上的普通 NLL 梯度，否则优化目标又回到了拟合验证答案，而不是任务奖励。

### 6.3 与 NICE 的关系

本框架借鉴 NICE：利用非可微任务指标对应的 policy gradient，估计训练数据对目标能力的影响。

当前拟采用的是“固定已接受 checkpoint、按技能形成目标、按需缓存样本梯度”的设计。它不是完整照搬 NICE 的多 warmup checkpoint 方案。梯度变换、优化器处理、归一化、投影与聚合方式仍需对照原方法确定。

## 7. Leval 怎样形成数据价值报告

### 7.1 先保留分技能价值

对于候选样本 x，形成它面向各技能目标的影响估计：

```text
x → 恢复能力影响估计
  → 回归保持影响估计
  → 工具选择影响估计
```

同一条数据可能对一个目标有利，对另一个目标不利。Leval 不应先将所有技能信息压缩为一个无解释的分数。

### 7.2 再汇总候选子集

报告至少包含：

- 各技能的影响估计及其分布；
- 实际技能、来源与任务覆盖；
- 重复程度、监督 token 与计算成本；
- 已计算的样本比例、缺失值和异常；
- 与当前最好方案相比改变了什么；
- 哪些是计算观测，哪些是原因假设。

第一版可以按固定规则聚合样本影响，作为局部收益代理。聚合权重应与实际 SFT loss 和预算定义一致。**样本分数可加是一种近似，不保证批次互补、冗余和多步训练效应都被捕捉。**

本轮的目标权重、保持要求和比较规则应事先确定。Lopt 可以调整数据配比，但不能通过修改评价口径让自身策略看起来更好。

### 7.3 可靠性的边界

内层输出的是“预计值得训练的子集”，不是“已经验证训练有效的子集”。需通过少量前期实验检验影响估计与真实训练结果的关系，并用外层反馈持续观察预测偏差。

## 8. 梯度缓存：同一模型下按需计算

### 8.1 基本机制

1. Lexec 得到候选子集。
2. 根据 checkpoint 和计算配置查询样本缓存。
3. 命中则读取，未命中才做前向、反向。
4. 保存压缩梯度特征，必要时保存它面向各技能的影响分数。

例如，A 策略处理过 1,000 条数据；B 策略选出 1,200 条，其中 800 条与 A 重叠，那么 B 只需新增计算 400 条。总处理量为 1,400 条，而非 2,200 条。

计算量取决于候选子集去重后的并集及其 token 长度。策略间重叠少时，缓存收益也可能有限。

### 8.2 缓存身份

缓存至少绑定：checkpoint、样本内容版本、tokenizer/模板、监督掩码与归一化方式、参数或 LoRA 表示、梯度变换和投影配置。若估计依赖优化器状态，也要绑定相应状态。

只保存整个批次的总梯度，无法支持任意样本重组；需要样本级或明确可重组单元的特征。保存完整梯度可能过大，因此压缩方式需结合实际资源确定。

### 8.3 接受与拒绝后的处理

| 外层结果 | 缓存处理 |
| --- | --- |
| 接受 | 建立新 checkpoint 命名空间；旧特征保留为历史，不当作当前精确梯度 |
| 拒绝 | 继续使用旧模型，旧 checkpoint 对应的有效缓存可复用 |

同一版本前向中可兼容地收集 NLL、entropy，避免重复推理；但它们与梯度都需要明确 checkpoint 身份。跨轮刷新范围和频率仍是成本设计项。

## 9. 搜索停止与最佳策略保留

内层同时维护“当前尝试方案”和“历史最好可行方案”。只有满足质量、预算等约束的方案才有资格成为最好方案。

停止条件包括：

- 连续若干次没有达到预设最小改善；
- 达到最大搜索次数；
- 新增梯度计算或总时间预算耗尽；
- 没有可执行的新候选。

若估计含随机噪声，应避免把微小波动当成进步。最终输出策略、对应样本清单、评价报告和缓存版本，不重新抽样成另一份未经评价的子集。

“最好”仅指当前预算和估计规则下观察到的最好方案，不代表全局最优。

## 10. 外层 SFT、测评与参数提交

### 10.1 候选训练

从 M_t 创建临时分支，按固定训练预算做 LoRA SFT。assistant 的动作与回答参与监督，工具返回作为上下文；具体掩码与数据编译保持一致。训练完成后得到候选模型，尚未提交。

### 10.2 分技能自由执行

候选模型在开发验证集上自由执行，与当前已接受模型比较：

- 目标技能表现是否改善；
- 保持技能是否超出允许退化范围；
- 工具、环境和任务约束是否满足；
- token、工具调用或执行时间是否显著增加；
- 证据是否足够，是否需要复测。

比较应保持任务和评分条件一致，记录样本数、配对结果及随机性。接受规则预先确定，Leval 解释结果，但不能随意修改规则。

### 10.3 接受 / 拒绝

| 决定 | 参数状态 | 后续行为 |
| --- | --- | --- |
| 接受 | 候选参数成为新的已接受参数 | 更新三个角色的共享模型，刷新能力目标信号，进入下一轮 |
| 拒绝 | 已接受参数不变 | 保留旧状态和有效缓存，将失败证据反馈给 Lopt |

若重用候选模型在开发集上的生成记录计算新目标梯度，必须确认它与提交后模型参数、模板和采样配置兼容。只有成功率摘要不足以完成梯度计算。

### 10.4 拟合诊断的位置

训练前后在相同参考历史上检查 NLL，用于确认训练与监督实现是否正常；entropy 可作为额外诊断。它们不能代替能力实测，entropy 下降也不自动等于进步。

拟合诊断不必作为每个内层候选的独立试验，避免内层不断训练模型。

## 11. 三个算法的职责

### Algorithm 1：总体交替过程

```text
初始化已接受模型、开发任务、候选池与历史
建立当前模型的分技能能力报告与目标梯度
重复：
  固定已接受模型
  调用 Algorithm 2，获得最好策略及子集
  调用 Algorithm 3，完成 SFT 与接受/拒绝
  保存本轮历史，更新数据使用状态
  若接受，切换模型并刷新目标信号
直到总预算或实验停止条件满足
最后在未参与优化的测试集上报告结果
```

### Algorithm 2：内层策略搜索

```text
初始化基础程序与最好方案
重复：
  Lopt 提出或修改 operator 程序
  Lexec 执行并检查实际子集
  Lexec 对缓存未命中的样本计算梯度特征
  Leval 形成分技能价值与批次约束报告
  保存报告，必要时更新历史最好可行方案
直到停滞或搜索预算耗尽
返回最好策略及其实际评价过的子集
```

### Algorithm 3：外层学习与验收

```text
从已接受模型创建候选分支
使用选定数据做固定预算 LoRA SFT
执行拟合诊断与分技能自由任务测评
按照预设规则决定：
  接受 → 提交参数
  拒绝 → 已接受参数不变
保存预测、实测和决定原因
返回已接受模型与本轮反馈
```

## 12. 每轮需要留下的记录

| 记录 | 内容 |
| --- | --- |
| 策略 | 程序版本、算子参数和连接、修改理由、父版本 |
| 批次 | 样本 ID、分支计账、技能与证据分布、重复关系、token |
| 影响估计 | checkpoint、目标任务版本、梯度配置、分技能估值、缺失情况 |
| 训练 | 起点、预算、LoRA 与优化器配置、候选 checkpoint |
| 能力测评 | 分技能前后表现、配对记录、奖励、生成轨迹、成本 |
| 决定与经验 | 接受/拒绝、原因、预测偏差、暂缓组合、待检验假设 |

历史结论必须附带模型状态和实验条件。例如“该组合在当前预算下退化”，不能直接泛化成“某类数据永远有害”。

## 13. 已确定的设计与待确认的问题

### 已确定

- 双层结构：内层固定参数搜索，外层训练并验收。
- 三个角色共享模型权重、保留独立角色记忆。
- 以独立 operator 组装筛选程序。
- 候选子集产生后才计算其样本梯度，按需缓存并复用。
- 能力开发任务按技能划分，同时服务内层目标与外层决策。
- 接受才提交参数；拒绝保留原参数与经验。
- 最终测试集不参与优化。

### 待实现或实验确认

- 具体技能体系、证据标注规则和可靠性。
- NICE 思路在长轨迹 agent 上的实现，包括奖励、梯度变换和压缩。
- 样本影响聚合为批次价值的规则及其预测有效性。
- 开发任务执行次数、随机性与接受阈值。
- operator 空间大小、搜索预算和停滞阈值。
- 跨轮 NLL、entropy 与梯度的刷新成本。
- 参数更新是否同时改善策略设计与评价能力。

当前框架的核心假设是：**在固定模型下复用梯度证据，可以帮助 Agent 比较数据选择程序；真实训练反馈再纠正这些预测，使后续选择更适合当前模型。** 这一假设的有效性与总成本，需要通过实验建立。
