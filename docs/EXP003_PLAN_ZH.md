## 实验三：控制学习、外部baseline及消融

| 内容 | 本次确定 | 待定 |
|---|---|---|
| V4控制学习 | 在V3基础上加入筛选/策略轨迹学习，构成完整架构 | 轨迹构造、准入、训练目标、格式、预算及训练位置 |
| 外部DS baseline | 接入用户后续提供的对比work脚本 | 具体工作、入口与依赖；不得自行虚构已接入 |
| 筛选轨迹有效性补充测试 | 对已经训练好的checkpoint执行用户设计的测试 | 测试题、指标、协议；默认不新增训练，不据测试反选checkpoint |
| 多agent→单agent消融 | 单agent承担Lopt/Lexec/Leval，统一prompt和共同历史，不做角色隔离 | 单agent的具体指令、上下文预算及调度格式 |

V4中真实任务子集SFT与控制轨迹SFT分别保存数据、参数父子关系和成本。控制学习方法未定前不提前发布空白轨迹训练为已实现；控制轨迹不冒充原任务池样本。最终benchmark及隐藏判分信息不能进入控制训练语料。

单agent消融改变角色组织与记忆：共享同一个agent会话/历史及统一prompt，保留相同外层训练、数据预算、工具、确定性算子和验证接口。它不是删除Leval的数值计算。能力差异、调用次数、上下文token和费用一起报告；不能把三份历史简单拼接却仍声明“历史隔离”。未来配置应区分shared_weights_separate_context与single_agent_shared_context。

外部baseline保留其原方法定义，额外报告对齐后的数据池、质量准入、训练预算、模型起点、任务协议及成本；不能偷偷复用V4更新后的模型作为baseline起点。无法等价对齐的项目单独说明。

## 本实验的依赖与隔离

方法参考[实验二](EXP002_PLAN_ZH.md)的V3和定向刷新规则，但不是接着实验二的训练run继续执行。方法比较应从共同M0出发；可核验复用只读数据、环境、M0开发测评及初始指标，不能直接继承V3最终权重后与从M0开始的baseline比较。

V4、各外部baseline和single-agent消融各自保存配置、精确训练数据、模型父子关系、轨迹、缓存和成本。具体轮次、控制学习方法、训练位置和总预算由本实验配置单独冻结，不自动继承实验二的运行状态。

## 本实验落地顺序

1. 用户确定控制轨迹学习方法后，实现V4训练流程及CPU验收。
2. 收到对比work脚本后，分别接入baseline适配器，核验公平比较条件。
3. 在已训练checkpoint上按用户后续协议开展筛选轨迹有效性测试；默认不新增训练。
4. 实现统一prompt、共享history的single-agent消融，冻结预算，再独立运行。

目前轨迹学习方法、补充测试细则及baseline脚本仍待提供/确定，不擅自填入。
