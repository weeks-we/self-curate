# 实验二：动态评分与动态程序

更新：2026-11-18。本实验独立规划、配置、workflow、handoff、运行及验收。本文是计划，不表示正式实验入口已经实现。

## 共享资产与比较边界

复用同一基础模型M0在分技能开发任务集上的结果、完整候选池的M0 NLL/entropy；身份一致时复用EXP001首次策略、标签、题单及环境。须核对模型/adapter、tokenizer/template、数据成员与内容、技能版本、损失口径、测评协议和checksum。变更任一相关身份时不强行复用。

各方法独立从相同M0出发，不把V1训练权重交给V3当起点。累计训练样本/token预算、轮次、学习率与训练超参、测评预算及最终benchmark协议应在配置中对齐；具体数值未在本次新增决定。共享只读资产，输出、使用历史、缓存版本、策略历史、权重和成本账本按分支隔离。最终benchmark不进入Lopt上下文或策略选择。

## 实验二：动态信号与动态程序

| 分支 | 固定项 | 更新项 | 内层验证 |
|---|---|---|---|
| V1 动态评分 | 首次制定的筛选程序及其阈值、权重、配额、顺序与分支 | 外层训练后，按下一轮Lopt主要提升方向刷新相关未使用样本的NLL/entropy | 不引入五次程序搜索；是否另做诊断需独立配置 |
| V3 动态程序，不训练控制轨迹 | 当前内层的模型参数、开发任务集及评价口径 | Lopt修订筛选程序；跨外层更新模型及定向指标 | 三个外层数据训练轮次，每轮五次内层候选评价；NICE或候选SFT待定 |

V1里Lopt后续可以给出技能方向，但不能借此修改固定程序、阈值、配额或运行顺序。方向只控制指标刷新范围。若以后希望方向同时直接控制筛选配比，需要另立变体，不能继续称为纯动态评分。

V3每轮内层评价实际执行的候选子集，结束时交付历史最佳的已评价程序和精确manifest。若选择候选SFT验证，各候选必须从同一本轮reference独立训练，不能串联训练；候选权重不提交为外层模型。若选择NICE，只做规定的前向/反向，不执行optimizer.step。两种验证方式不能按候选表现临时切换。

这里的“3×5”是三次外层训练、每次五次内层候选评价；若计入初始M0能力测评，则有初始点加三次训练后共四个能力节点。第一个候选是否直接复用初始策略需在EXP002配置中明确，但总评价次数不能暗中变为六次。

## V1/V3共用的定向刷新时序

1. 首轮加载全池M0 NLL/entropy；没有合法资产才计算并发布，不按技能缩减初始化范围。
2. 当前外层选定manifest后真实训练，保存精确曝光历史，执行开发任务集测评。
3. Leval整理本轮开发结果及历史，Lopt给出下一轮主要优化的技能方向；方向是结构化输入，绑定反馈和当前实际使用模型。
4. 在下一轮筛选前，刷新“方向技能并集内，且本分支历史上从未参与外层真实任务子集参数更新”的样本。随后执行固定程序（V1）或开展五次程序搜索（V3）。

不能在选样后、模型尚未训练/反馈尚未产生时就用旧模型冒充下一轮刷新。末轮没有下一轮筛选时默认不为它额外刷新。若接受/回退机制以后启用，刷新绑定决策后实际保留的模型；本次没有新设接受阈值。

“未使用”不等于“没被内层选中过”：内层筛选、NICE及候选验证SFT不消耗原池样本的外层使用资格；外层真实训练即使随后被退回，也保留曝光记录。部分训练状态不明时先阻塞，不当作未使用。以数据ID和内容身份匹配；不能通过换ID重新获得资格。

未刷新样本保留旧版本信号，不能改写为当前模型版本或填零。配置应显式允许读取哪些旧版本、怎样处理缺失值，并在每个operator回执记录实际使用版本。否则仅刷新部分数据后，要求全列当前版本的operator可能无法运行。梯度缓存继续独立按完整模型/数据/坐标身份管理。

## 本实验落地顺序

1. 核验EXP001的M0开发测评、全池初始指标和首次策略等可复用资产。
2. 独立建立EXP002配置/workflow/handoff；V1与V3分别设分支、使用历史、输出及成本账本。
3. 冻结NICE或候选SFT验证方式、训练预算、方向prompt、信号版本读取和五次候选计数规则。
4. CPU验收三轮流程与恢复，再进行服务器环境和真实实验验收。

本实验不包含控制轨迹训练、外部baseline接入或single-agent消融；这些属于[实验三](EXP003_PLAN_ZH.md)。
