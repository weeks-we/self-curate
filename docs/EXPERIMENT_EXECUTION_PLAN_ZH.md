## 2. 把数据准备接到实验主线之前

数据准备是多个实验共用的前置任务，不是新增一行算法性能对照。第一次框架实验前实现并执行：

1. 固定来源，恢复作者精选 ID，精确匹配 tool 轨迹，不按任务 ID 随便替代，不凑数。
2. 静态准入与隔离账本，保留全部原始数据及排除原因；静态检查、来源成功与当前执行验证分别记录。
3. 七技能 mock 对齐检查 → 30 条分层 pilot → 在明确 API/预算授权内标注；疑难项与不完整覆盖保留缺失/复核状态。
4. 用真实 tokenizer/template/assistant mask 对齐证据并统计；缺少实际 tokenizer 时 pending，不用字符数冒充 token。
5. 排除完整作者精选对应任务及家族，抽开发技能组并产生去重 union；任务多组引用，不重复执行同一 rollout 配置。
6. 注册最终测试版本、全量/可选 subset 清单、交集及资源约束；此阶段不做目标模型推理。
7. 发布来源锁、候选池、标注/准入/隔离报告、开发/测试 manifests 和费用。未来生产模块负责相应语义验收，资产层负责快照、身份、完整性和依赖。

之后由独立的模型/执行模块生产 M0 能力测评、首次精确 NLL/entropy、需要的参考执行与初始策略，登记为共同资产。数据准备 prompt 不承担这部分推理/计算工作。

候选池、技能体系、模板和划分不变时，后续实验直接引用匹配资产；改变它们时发布新版本，保留旧版本。改变 target 权重并不自动要求重新做与 target 无关的静态技能标注；NLL/entropy、目标执行与梯度必须绑定相应模型状态。

## 3. 推荐推进顺序

| 顺序 | 工作 | 复用与交付 |
|---|---|---|
| A：共享准备 | 上述数据准备、目标模型/tokenizer 与真实任务执行适配 | 版本锁、M1 池、开发/测试 manifests、可恢复账本 |
| B：共同起点 | M0 开发测评、初始精确指标、初始策略；核验已有 NICE 一致性结果能否按相同协议复用 | 三类共享资产；不能仅因已有实验跑过就直接当共同结果 |
| C：NICE 路线确认 | 按原计划完成必要校准，固定 NICE 或短期 SFT 主评价路线 | 校准结果/协议与成本；不自动两条路线都跑主表 |
| D：V0/Random | 共同约束、预设两次尝试和曝光预算，关闭控制轨迹 SFT | 固定 manifests、阶段权重、逐题结果、接收/拒绝与成本 |
| E：V1 | 当前模型精确信号刷新，程序和参数固定 | 新模型命名空间、刷新记录与新选集 |
| F：V2/V3 | 依次开放参数编辑/程序结构编辑，匹配信息与资源 | 结构/参数 diff、历史最佳精确选集、全部反馈 |
| G：V4 | 合格控制语料、冻结控制训练模式、固定学生的控制器对照 | 单独控制曝光/成本、无未来信息泄漏的语料与真实后续分支 |
| H：效率/正式 | 锚点审计、所选近似刷新真实分叉比较、冻结方法、主表/外部基线及必要消融 | 固定方案、可比成本、重复运行与配对统计；General 独立训练 |

完全匹配的共同前缀可共享；首次选集或参数路径分歧后，继续各自真实运行。V0 的两个静态阶段提前确定；V1 不修改策略；V2 结构固定；V3 才开放结构；V4 才开启控制学习。两次外层尝试不等于任务子集与控制轨迹两种 SFT，拒绝仍消耗尝试和预算。

## 4. Handoff、配置与控制代码各管什么

- **配置**保存实验变量、共同协议、输入 AssetRef、预算、seed、停止/接收规则和输出位置。
- **控制代码**实际核对配置、装配模块、管理状态、两次尝试、缓存/重算、权重接续、失败恢复和费用，不因 LLM 改写研究定义。
- **Handoff**告诉服务器 Claude 执行哪个已就绪入口、固定哪个版本、复用哪些资产、做到哪里、失败如何报告，以及交付哪些文件。

Handoff 可以让常规操作无人逐步指挥，但不能代替尚不存在的控制逻辑。模块或必填研究参数缺失时不能靠临场猜测跑出一套“类似实验”。未实现命令不得出现在 ready 的执行交接里。

每个逻辑实验使用一个带版本的 handoff；代码/共同手册只维护一份。真正准备执行时才新增具体文件，重试/恢复引用原 handoff、原配置锁和原 run 状态；协议、预算或方法发生变更时另建版本/运行，不覆盖已经执行的定义。

## 5. 已确认并实现的刷新规则

0.12.0 新增 [定向刷新接口](FOCUSED_SIGNAL_REFRESH_ZH.md)：第一轮全池初始化；第二轮起接收未来 Lopt 流程给出的技能方向，仅刷新方向并集内、从未参与本参数分支外层真实子集更新的数据。内层选中/试训不算外层使用；外层训练后退回仍算已用。方向缺失则等待，不自动全量刷新。

指标绑定当前接收 ModelRef，旧版本保留；同身份已有完整值复用，不重复前向。提供完整计划/前后快照/费用/严格重载，以及可选 OuterCycle 使用历史跟踪。范围与模型变化后创建新内层 context，不改变正在运行的内层。

Lopt 方向推断、实验级自动调度/跨进程恢复、分片排程与近似刷新仍未实现。V0 继续保持 M0 静态教材，由未来实验控制配置显式决定是否调用刷新；不能混用各变体的更新定义。

## 6. 目前不只是缺刷新策略

已有：M1/M2/P0/P1、指标计算与多版本回填、首轮全量/后续定向精确刷新、两种 Leval、内层搜索、单次外层两种 SFT、共享资产与输入锁。

首次正式实验前仍需接通：实际数据准备/标注模块、目标模型/tokenizer 和任务执行适配、实验控制入口/两次尝试接续、V0/Random 关闭控制训练路径、预设停止/接收/预算规则、必要的恢复与结果汇总，以及真实服务器 smoke。V2/V4 的额外能力在各自阶段前实现。

下一轮可编写首次实验的配置、缺失控制代码与具体 handoff，接入数据准备和真实后端；具体 handoff 全部检查通过后才标 ready。新增刷新模块不意味着统一实验入口和真实执行已经完成。
