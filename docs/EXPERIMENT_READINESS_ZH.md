# 渐进实验就绪审计与推进清单

日期：2026-11-07。审计对象：Self-Curate 0.10.1。依据：用户提供的 RSI_Progressive_Experiment_Plan.md（2026-11-05 修订版）及 RSI_Data_Preparation_Codex_Spec.md（v1.0），结合当前源码、接口和实现决策。

后续更新：0.11.0 已补 [共享资产保存/复用与服务器更新规范](EXPERIMENT_ASSETS_ZH.md)，包含 M0 测评、NLL/entropy、初始 Lopt 调用及冻结运行输入。下文关于统一实验 runner、两次尝试接续、V2/V4 权限、真实执行和完整恢复的缺口仍存在；资产层不等于实验控制层已完成。

0.12.0 更新：已实现 [首轮全量初始化、后续技能方向且外层未使用样本的精确刷新](FOCUSED_SIGNAL_REFRESH_ZH.md)，包含分支外层使用历史和严格输出重载。技能方向由未来 Lopt 流程传入；统一实验调度与真实参数接续适配仍待实现。下文是原审计基线，相关刷新缺口以本段和接口文档为准。

本次是代码与渐进实验计划的静态审计；数据准备规范仅用于明确接口边界，不作其逐条实施验收。不执行附件内的数据下载、外部标注、训练或 benchmark 指令，不实现新的算法，不将既有微型 CPU/mock 验收当作真实实验成绩。用户已单列的数据/标签/benchmark 准备、目标模型权重适配和指标刷新另行推进；以下重点列出此外的缺口。

## 1. 结论

现有数据契约、筛选器、NLL/entropy 数值内核、两种 Leval、内层搜索和单次外层训练可以复用。完整 V0–V4 尚不能只通过一份控制文件运行。

最需要补的是配置化实验组织、变体权限、跨尝试状态转移、可重载资产与真实执行适配。按这几项建设共享接口，后续同类实验可以主要增加配置；尚未具备的研究能力（例如控制数据生产、混合训练和固定学生的控制器对照）仍需一次性实现，不能靠填写配置凭空获得。

两个边界澄清：SignalService 已能在传入新 ModelRef 后重算数据、保留多版本并回填；0.12.0 已补轮次/方向/外层使用约束，但实验级自动调度和近似刷新仍未实现。权重侧也已有通用 StateDictModelStore，目标 Transformer/PEFT 模型的完整适配仍待接入。

## 2. 计划与当前执行语义的关键差异

### 2.1 两次外层尝试，不等于两种 SFT

计划要求每个递增配置先做两次外层训练尝试，拒绝也消耗一次尝试和对应训练预算。当前 OuterCycle 管理的是一次 stopped search 后的“subset SFT → 验证/判断 → curation SFT → 验证/判断”。

因此需要上层实验状态机管理 attempt_1/attempt_2、已接受参数、拒绝后的旧模型、使用历史与下一次筛选。每个 attempt 内是否执行 curation 由变体决定。原有单次训练/验证模块继续复用。

权重接续还需要明确 checkpoint 注册：当前 StateDictModelStore.load_branch 只接受其 initial ModelRef，TorchSFTBackend 的 _produced 映射保存在该实例内。训练出的新 checkpoint 供下一轮 signals/NICE/角色服务加载、或跨进程恢复，需要统一的模型引用解析；保存权重文件本身不能完成这项接续。

代码依据：[OuterCycle](../src/self_curate/orchestration/outer_loop.py)；state 明确记录 resume_implemented=False，accepted.json 属于本 attempt。

### 2.2 V0–V3 必须能够关闭控制轨迹训练

当前 OuterCycle 要求同时提供 subset_recipe/curation_recipe，subset 接收后进入 awaiting_curation_data。尚无正式的 curation=off 完成路径。固定策略也没有无需伪造搜索历史即可进入外层的统一 handoff。

需要定义共同的选择结果消费入口，保留原精确 manifest、版本和训练顺序校验。固定程序和搜索最佳候选都能提供该入口；V0/V1 不必伪装成运行过 Agent 搜索。不能以空控制数据或训练后卡在等待状态代替关闭控制学习。

### 2.3 V2 与 V3 的编辑权限尚未硬隔离

EditPolicy 现有 share/证据步长、节点数量、模型尝试与 seed 限制；_validate_candidate 校验合法子程序、编辑数量、配额和 seed。没有独立的“只能改指定参数，禁止改结构”规则。

V2 需要冻结节点 ID/op/inputs/output 等结构身份，并限制可修改参数路径。V3 再开放预设结构编辑。两者继续共享信息、工具权限、评价协议和搜索资源上限。仅在 prompt 写“不要改结构”不足以构成实验控制。

代码依据：[EditPolicy](../src/self_curate/contracts/feedback.py)、[_validate_candidate](../src/self_curate/agents/lopt.py)。

### 2.4 V4 的固定学生对照需要独立模型组合

RoleRuntime 目前将三个角色绑定同一个客户端和 ModelRef，这是主框架已明确的约定。计划 10.1 要求固定学生和其他角色，只替换 Lopt 权重；当前一个共享 runtime 不能表达该对照。

建议保留主实验的共享参数模式，在专用控制器交叉实验组合器中显式绑定 student/controller/其他角色身份。相同开发证据、历史、评价工具和预算必须固定，不能因控制器变化顺带重算另一套学生目标。该模式在 V4 前实现和验收，不默认改动现有共享约定。

## 3. 其余缺口及可复用部分

| 项目 | 现有能力 | 尚需补齐 |
|---|---|---|
| 实验控制入口 | 各模块 Python API、若干 CLI、fixture/demo 配置 | 统一 ExperimentSpec、配置解析/冻结、依赖装配、正式 run/resume/audit/compare 入口；当前没有 run-experiment 命令 |
| 多尝试接续 | 单次 OuterCycle、精确 best、attempt 内接收/退回 | 2 次尝试的状态机；新已接受模型供下一次 Team/context/评价/评分使用，拒绝保留旧参数；必要的跨轮经验转交 |
| 真正 Agent 调用 | SharedModelClient 协议、固定 prompt 外壳、独立 history | 实际本地模型/推理服务客户端、结构化回复、服务权重身份和用量；三个 instructions 当前为空，实验前需冻结正文 |
| 真实任务执行 | TaskRunner 协议、TaskValidator、逐任务结果/费用 | 生成、工具交互、环境执行、预算落实、评分以及 NICE 实际动作 token 重放适配；准备好任务文件仍不等于这些已实现 |
| NICE 直接选择 | 按给定候选计算样本×任务 cosine、验证报告及证据 | 版本化逐样本评分/排序资产及共同约束下的直接选择桥接；现有 SampleSelect ranked 消费已有顺序，不自动按 NICE 排序 |
| 可跨进程精确缓存 | 完整身份、内存缓存、指标/向量落盘，SFT 基线可显式恢复 | 通用的样本/目标特征重载与完成标记校验、缓存查询/命中成本；不能把导出 vectors.npz 等同于实现了进程重启缓存 |
| 控制语料生产 | 角色 before/after、请求/反馈/程序/历史证据，TrainingData/JsonCurationDataProvider | 从当时可见上下文构造修订样本、质量门禁、assistant mask、去重及来源链；目前 JSON provider 只读取已经做好的语料 |
| 控制训练模式 | 子集后顺序训练 curation，分别验证/判断 | 配置 off/sequential；如采用计划中的混合 SFT，另补任务/控制采样与 loss 权重；明确曝光和额外预算，顺序训练不能自动等同混合训练 |
| 停止与接收策略 | StopCondition/DecisionProvider 接口，缺配置会等待 | 把预先确定的规则实现为确定性策略并从配置装配；不代填研究阈值，不隐式接受 |
| 恢复与阶段权重 | 内层可恢复；训练结束保存权重、optimizer/RNG；外层写 journal | 实验/外层恢复、训练中间阶段 checkpoint、加载 optimizer/RNG 的继续执行路径；已有 training_state.pt 不等于已有恢复实现 |
| 总预算与公平性 | BudgetPack、单请求训练预算核验、CostLedger | 实验级 2B 尝试曝光守卫、拒绝消耗、任务/控制 token 分账、唯一 ID/累计曝光、候选 SFT 与角色/评分/环境/I/O 成本汇总 |
| 最终测试执行 | TaskRecord 有 test split；当前 TaskSuite 仅允许 development | 保持开发/最终测试隔离的最终评测入口、冻结权重后执行；不修改现有 development guard 来让最终测试进入优化 |
| 结果与对照管理 | 每模块结构化结果与 provenance | 统一逐尝试结果表、逐题和分技能表、共同任务的配对分析、预设重复运行、实验 diff、缺失/失败统计和对照矩阵 |
| 真实规模执行 | 可选 CPU/CUDA 后端，Torch SFT 参考实现 | 目标模型容量/吞吐验收和必要训练/服务适配；当前 micro-batch=1，无 scheduler/分布式等通用实现，按实际实验需求补最少能力 |

缓存细节：SignalService 的完整同版本聚合值可从附带 signal 的 M1 记录复用，scoring batch 可以重载；逐 token _tokens 仍是内存缓存。TorchNICEBackend 的 _samples/_targets 也在内存，虽导出 vectors.npz，但没有持久化样本特征 cache loader。SFTValidator.save_reference/restore_reference 已存在，不应重复建设另一套基线系统。

跨轮经验细节：LevalContext 故意只比较同模型/objective/context/protocol 的观察。新 checkpoint 的经验转交须区分“可供解释的历史”和“可比较的当前数值”，不得放宽这些校验把旧分数当新证据。

NICE 是单 checkpoint 的 fresh-Adam/cosine 代理，输出 predicted_gain；SFT 验证输出 reward_delta。现有不同量纲/协议隔离应保持，不将代理解释为实际能力增益或真实优化器更新的等价形式。主路线由正在进行的一致性验证决定。

## 4. 每个实验应保存和复用什么

| 资产 | 复用条件 | 后续用途 |
|---|---|---|
| 来源锁、规范化轨迹、静态质量/技能标注、split/家族隔离 | 对应内容、来源、技能体系、tokenizer/template/mask 等身份一致；不依赖变化模型的标签不需每轮重做 | V0–V4 共同输入 |
| M0 的 NLL/entropy、精确梯度、NICE 参考执行与重放 | 模型/adapter、实际输入/监督、目标任务/采样/重放、参数坐标、投影/变换、实现数值条件等完整匹配 | 共同起点/相同条件复用；M1 不能冒充 M0 |
| 精确 BatchManifest 和训练顺序 | 同程序、数据快照、预算/约束和模型条件，消费原清单 | 固定 V0 两阶段选集、同前缀与同候选对照 |
| checkpoint、训练配方、optimizer/RNG 状态、位置/曝光计数 | 前缀决策、初始参数、数据顺序、配方和数值条件一致；权重接续与完整训练恢复分别声明 | 从首次分歧处分支，避免重复训练共同前缀 |
| 逐候选程序、当时反馈、完整角色事件与已知/未知成本 | 保留原时间顺序、模型/协议与实际调用身份 | 后续控制语料、失败案例、结构/信息消融 |
| 逐任务/seed 执行与评分、能力报告 | 模型、环境、采样、任务套件、评分协议和预算完全一致；不越过最终测试隔离 | 同条件验证复用、分技能/配对分析 |
| 预测器审计的真实锚点 | 同一审计 checkpoint/样本/目标指标的精确真值；训练/校准/测试拆分冻结 | 平均变化/岭回归/MLP 共享监督，减少重复精确计算 |
| 冻结配置、父资产引用、源码/环境/模型与数据身份、总成本报告 | 内容 hash、完整性和依赖校验；来源为正式还是 mock 明确 | 判断早期结果是否有资格进入正式比较 |

资产注册表只记录引用、内容身份、依赖、完成状态和来源；M1 指标查询继续用 MetricView。缓存命中应验证实际文件与完成标记。复用以引用表达，不改写原实验快照、manifest 或成本账本。

跨实验复用还需区分实际物理成本、逻辑训练曝光与摊销/从头运行成本。同一已发生计算不能重新登记成另一笔物理事件；实验质量比较也不能因命中旧缓存而漏报训练曝光或优势资源。相同前缀只在完整身份匹配时共享，方法名相似不足以证明相同。

## 5. 用最少共享代码支持配置化实验

建议新增一个小的 experiments 组织层，只包含三项职责，继续调用原模块：

1. **Spec/装配**：严格解析共同协议和变体差异，冻结配置 hash，绑定依赖；未知字段拒绝。注册固定后端/策略，不让控制文件执行任意 Python，也不让 Lopt 改评价协议。
2. **Runner/状态**：处理尝试次数、模型接续、变体权限、停止/接收、阶段和恢复。复用 prepare_selection、内层搜索、TrainingService、TaskValidator 等；固定程序不运行 Lopt 搜索。阶段权重发布与恢复利用既有 artifact/checksum，不另造 ModelRef/BatchManifest。
3. **资产/汇总**：发布及解析上述可复用资产引用，做身份与完整性审计，输出共同结果/成本表。保持文件式管理，不引入数据库/工作流服务等额外基础设施。

在 experiments 层共用 V0–V4，避免 v0_runner.py/v1_runner.py 等各自复制算法。真实模型/Agent/任务适配仍放在原所属模块，控制语料与刷新能力按阶段补齐。

建议的变体权限表（待实现）：

| 配置 | 选集 | Lopt 编辑 | 控制 SFT |
|---|---|---|---|
| Random | 明确预选或逐轮抽样，共同约束/曝光 | 关闭 | 关闭 |
| V0 | M0 下预先冻结两阶段 manifest | 关闭 | 关闭 |
| V1 | 当前已接受模型的精确信号；固定程序/参数重新选择 | 关闭 | 关闭 |
| V2 | 同 V1 的当前信息与共同评价 | 参数白名单，结构固定 | 关闭 |
| V3 | 与 V2 相同的信息/评价/搜索资源 | 允许预设结构编辑 | 关闭 |
| V4 | 与 V3 相同的选择机制 | 同 V3 | 开启已冻结的控制训练模式 |

所有配置先做两次尝试；B、seed、学习率/优化器接续规则、数据复用、停止/接收标准由实验前配置明确给定，不在审计中虚构数值。拒绝仍计入预算，下一次从旧已接受模型出发。

配置建议拆为：共同协议、当前变体、可复用输入引用、冻结后输出快照。初期不建设复杂配置继承系统；共同配置加显式变体覆写并做 diff/合法性检查即可。未来 run-experiment/resume-experiment/audit-experiment/compare-experiments 都属于待实现 CLI，当前不能直接运行这些名称。

## 6. 按阶段推进的最小顺序

1. **V0/Random 前**：完成实验 Spec、固定选择 handoff、控制训练关闭路径、两尝试接续与预算、实际任务/模型后端、停止/接收策略、资产保存/恢复和共同报表。需要 NICE 直接排序时同时补评分资产桥接。先用微型 CPU/mock 走完接受和拒绝两条路径，再做真实服务器 smoke。
2. **V1 前**：接入当前模型的精确刷新，重建 Team/context/目标评价命名空间；同 checkpoint 资产可复用，新 checkpoint 不拿旧值冒充。近似预测不进入此阶段。
3. **V2 前**：真实结构化 Lopt 客户端、冻结 prompt、参数编辑白名单及相同信息/资源约束。改结构必须被代码拒绝。
4. **V3 前**：开放合法结构编辑，保存实际结构 diff 与选集 diff；核验 V2/V3 可见信息和预算一致。冻结模型不允许内层任意晋级。
5. **V4 前**：整理合格控制样本，落实无未来结果泄漏的 mask/来源链，冻结顺序或混合训练规则、控制额外 token 与任务曝光，补固定学生的控制器交叉实验。
6. **效率/正式实验前**：精确锚点、预测器审计和预测身份、真实分叉训练、统一冷/热缓存/I/O 成本，冻结正式方案。补外部基线适配、最终测试入口、重复运行/配对统计和 General 任务适配。

每阶段先确定共同接口/验收，再新增配置。无需一次实现所有效率预测器、外部方法和 General 变体；本轮未实现的能力应在管理清单保持“待实现”，不能把示例配置当成已支持功能。

## 7. 建议的首个下一任务

先完成“配置化 V0/Random 两尝试执行与资产保存”这一垂直模块：固定 seed、冻结两个静态选集/随机协议、任务 token 预算、关闭控制 SFT、接收/拒绝后的第二次尝试、checkpoint 引用和结果/费用表。

验收要求包括：配置不支持的选项在执行前失败；相同 seed/输入可复现；拒绝消耗一次尝试；原始数据和已保存资产不可覆盖；恢复不重复调用已完成训练/评分；从冻结 manifest 消费精确成员与顺序；新模型开启新数值命名空间；task/control/拒绝成本不混记。服务器容量或真实环境尚未通过时，明确返回未验收状态。

此任务完成后，逐步添加 V1 刷新、V2 参数权限、V3 结构权限、V4 控制学习。当前已有 605 项本地历史验收是模块工程基线，本次静态审计没有重新运行测试、目标模型、GPU、API 或任务环境。
