# 实验一更新：20k数学池、标签、训练依据与集群评测

本文件优先于此前实验一文档中的候选池、比例与开发题准备顺序。2026-11-20 更新。

## 已确定的流程

模型仍为 Qwen3.5-9B，关闭 thinking。三领域各自运行 Initial、Full、Random 5%/10%/20%/30%/50%，共21个评测分支、18次独立SFT、84组benchmark结果。所有随机比例来自同一个固定排列；累计训练曝光约为每个完整池的2.15倍。Full是全量数据、LoRA训练，不是全参数微调。

模型、数据和benchmark只登记可访问的官方HF链接及revision；这轮不要求本地完整下载或构建镜像。来源表为 configs/ordinary/sources.json。

## 数学20k池：已查真实字段，不能直接冒充SFT数据

[Artemis0430/NuminaMath-20k-Stratified](https://huggingface.co/datasets/Artemis0430/NuminaMath-20k-Stratified)，固定revision：02f49adbe185cf9b921407bf92ef9f65f29d4609。

真实字段只有 data_source、prompt、reward_model。抽查问题的 ground_truth 是 `12`；没有分步solution、problem_type或可直接用于本项目的技能标签。数据卡按GPT-OSS-20B的8次尝试通过率分五档，每档4000题；这是难度分层，不是五种数学技能，当前记录也未提供逐题难度字段。

因此确认使用其20k题单，但数学SFT还需：从原始来源按题面准确关联参考解答与来源，或另行生成并校验解答；同时完成数学技能标注。不能只凭最终答案伪造完整解答，也不能声称已恢复原始题目ID。适配器对未补齐的原始20k格式明确报错。没有找到该仓库直接提供完整SFT参考解的证据。后续应保存source row hash、题面hash、参考解来源、关联状态和技能版本；未能准确关联者单独列出，不模糊匹配后直接训练。

## 标签设计（任务所需能力，允许多标签）

代码沿用TACO官方八类，不再使用SWE过程行为标签：

| ID | 名称 |
|---|---|
| amortized_analysis | 摊还分析 |
| bit_manipulation | 位运算 |
| complete_search | 穷举搜索 |
| data_structures | 数据结构 |
| dynamic_programming | 动态规划 |
| greedy_algorithms | 贪心算法 |
| range_queries | 区间查询 |
| sorting | 排序 |

依据：[TACO官方说明](https://huggingface.co/datasets/BAAI/TACO)。保留原始skill_types和tags，明确一题可以需要多项技能。稀有技能未必有50道测试题；必须统计，不重复凑数、不私自合并。

数学建议七类：algebra（代数，含方程/不等式/函数）、geometry（几何）、number_theory（数论）、combinatorics（组合计数）、probability（概率统计）、calculus（微积分/极限）、logic（逻辑推理）。标注问题的实际求解能力；一题可跨域，不用难度或数据来源替代技能。无法判断的送复查，不给other当成一个能力。20k池缺少这些字段，因此数学技能仍需要准确来源继承或teacher补标；本轮未调用付费teacher。

IF沿用约束功能，十组：lexical（关键词/禁词）、format（结构格式）、length（词句段数量）、required_content（指定内容）、boundary（开头结尾）、language（语言）、case（大小写）、punctuation（标点）、composition（组合约束）、style（文体）。实际映射以原始constraint前缀为证据，不凭答案风格猜标签。未知前缀保留原值并列为未映射；先完整审计再冻结是否保留所有稀有组。不能声称这些标签自带全部可执行kwargs。

每组50题是开发集需求；标签种类不必强制互斥。分技能结果的分母分别统计，同一任务只执行一次，所有技能成员计数的总和可能超过题数。

## 长度字段

主筛选长度建议用 **answer_tokens**，即固定目标tokenizer下assistant正文的token数；它最接近监督量。另保留answer_chars（字符数）、prompt_tokens、完整聊天input length。既有length字段继续表示完整编码长度，不能改变其原义。不同模型tokenizer的长度要有不同版本；字符数可跨模型比较，不能代替token预算。TACO开发题同样记录参考解长度，不把测试输入长度当成答案长度。

实验一末尾完成标签审计与分布报告，再抽数学/IF每技能50题，余下发布为后续训练池；TACO从独立test1000题抽取开发题，不将剩余test题混入TACO train。保留唯一ID、skill groups、随机seed、原池hash、开发/训练文件hash。新命令：`finalize-labels --pool ... --completed-run ... --output ...`；TACO追加`--coding`。

必须区分：数学/IF若在实验一Full训练之后才抽开发题，它们已被Full checkpoint见过，不能独立验证这些checkpoint。可用于后续从原始基座重新开始、严格排除这些题的筛选实验。报告必须标记这一暴露关系。实验一最终成绩仍看独立benchmark。

末尾报告包括每技能唯一题数和占比、多标签率、缺标签/未知标签清单、少于50题的组、长度统计、开发/未来训练规模及交集检查。完整真实分布要等全池实际处理，当前没有伪造分布数字。

## 公司集群的判分安排

推荐：GPU作业只负责SFT和批量生成；生成答案与模型/题单hash落到共享存储；CPU判分作业使用固定环境读取答案，调用官方checker。二者不需要同时占GPU。

数学和IF主要是Python依赖，不需要为每题构建环境。代码执行应隔离；[BigCodeBench官方](https://github.com/bigcode-project/bigcodebench/blob/main/ADVANCED_USAGE.md)建议Docker，并单列Requirements/requirements-eval.txt，不能只安装bigcodebench包便认为函数库齐全。优先在工作站一次构建判分镜像，再在公司平台用其原生容器CPU作业运行，避免GPU容器内再启动Docker或挂载宿主socket。

Slurm/HPC若只有[Apptainer](https://apptainer.org/docs/user/latest/security.html)，可由管理员支持的方式在工作站准备SIF。但Apptainer默认共享部分宿主资源，不能把普通`apptainer exec`等同Docker隔离；执行生成代码还需平台批准的网络、文件系统、PID和资源限制。无论哪种引擎，官方测试/判分语义保持一致。

当前自动backend仍使用Docker调用，异步“GPU生成→平台CPU判分”调度尚未实现；这里只给推荐部署方式，不能宣称已有Apptainer或Kubernetes适配。选择取决于公司集群实际支持的容器/作业接口。

## 8×H200 141GB估时

约75,423条原始样本（TACO25443+数学20000+IF29980），准入后会减少。18次独立训练累计2.15倍，约162,159条nominal样本曝光。假设全池平均完整输入1500—3000 token，总训练输入约0.24—0.49B；假设全8卡合计5k—20k input token/s，纯训练算术约3.4—27小时。padding、保存、18次模型装载和初始化另加。

84组benchmark是较大成本：若合计生成约2500万—7500万输出token，8卡合计500—2500 output token/s，则约3—42小时，另加代码CPU测试。以上都是规划假设，非H200实测或承诺。

模型/解答/标签/环境准备齐全后，建议先预留 **1—4天** 做完整实验一计算和判分；数学解答补齐、标签费用和首次平台排障不在这个时长内。短任务样本数少时global32使5%分支只有几十步，epoch和warmup应在最终冻结时共同确认。
