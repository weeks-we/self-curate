# RSI 数据筛选：最新递进实验与消融执行方案

> 更新：2026-11-05；精简修订版。
>
> 当前进度：NICE 类估值与真实 SFT 收益的一致性验证正在运行。
>
> 核心安排：逐步加入模块，边运行边开发，通过统一配置积累递增消融；主要机制明确后冻结方法，开展正式主表和外部基线；最后只补必要的完整方法去除对照。

## 1. 本版范围

本版替代此前较重的逐项实验清单。实验主线收敛为：

**NICE 验证 → V0 静态选择 → V1 动态评分 → V2 动态参数 → V3 动态程序 → V4 控制学习 → 精确／近似刷新比较 → 冻结正式方法 → 主表与外部基线 → 必要后置消融。**

递增实验回答“加入这个模块有没有增量价值”；最终单模块去除对照回答“它在最终系统中是否仍有作用”。二者条件一致时可以复用，不一致时只补核心项。

不要求每次加模块都涨分。模块无稳定收益时，可以退出最终方法，或降为工程选择；不为保留框架复杂度而不断扩大实验。

## 2. 统一实验骨架

### 2.1 数据和验证

- Coding 优先，使用共同小规模 SWE-smith tool 候选池，固定 revision、质量准入与完整轨迹单位。
- 开发任务提前按技能分组，同一套开发任务用于内层评价和外层验收；最终测试独立，不参与逐个模块的选择。
- 同一任务的多条轨迹和近重复做好 split 隔离。技能可以多标签，分组结果有重叠，不当作独立证据。
- General 独立训练，后期复验核心机制，不完整复制 Coding 的所有消融。

### 2.2 阶段和预算

- 递增阶段统一先跑 **两次外层训练尝试**，观察第一次模型更新是否影响下一次选择。
- 每阶段任务监督 token 预算记为 B，总尝试曝光预算为 2B。B 根据当前训练计时确定，不在本方案虚构样本量。
- 拒绝的尝试也计入训练量与成本，不允许额外无限重试。报告最终保留模型及全部尝试成本。
- 固定训练配置、学习率接续、数据复用与验收规则。随机、静态配置也按相同阶段训练。
- 比较路径从共同初始 checkpoint 出发。完全相同的前缀共享，从首次决策分歧处建立分支。
- 前期用一个预先指定的 seed 检查可行性；关键比较再补重复运行和不确定性，单次正结果不直接作结论。
- V0–V4 优先用精确当前信号和同 checkpoint 精确缓存。近似刷新后接，避免误差混杂。

若更新被拒绝，下一次仍基于旧已接受模型，但保留历史。两次尝试不保证发生两次参数更新；需要如实说明。

### 2.3 固定角色与信息条件

V0–V4 采用共同实验骨架，角色组织、基础 prompt、报告格式、记忆规则先固定。V4 新增参数学习，不同时给予额外历史或工具。

V2、V3 匹配可见信息、评价器、工具权限与预设搜索资源上限，并记录实际调用成本。更大结构空间不自动配更多候选或更丰富反馈。

## 3. 五个递增配置

| 配置 | 数据选择 | Agent 策略能力 | 控制轨迹 SFT | 主要检验 |
| --- | --- | --- | --- | --- |
| V0：静态选择 | 初始模型下预先确定两个阶段的数据 | 无后续修订 | 无 | 静态教材参照 |
| V1：动态评分 | 每阶段按当前模型重新评分、选数 | 固定程序、固定参数 | 无 | 持续感知模型状态的价值 |
| V2：动态参数 | 当前评分、反馈和候选比较 | 修改阈值、权重、技能配比等 | 无 | 反馈式参数修订的价值 |
| V3：动态程序 | 与 V2 相同的评价机制 | 再开放算子组合、顺序和分支 | 无 | 程序结构自由度的价值 |
| V4：控制学习 | 与 V3 相同的选择机制 | 同上 | 加入合格策略修订记录 | 参数学习是否改善后续选择 |

V0 也分阶段训练，只是阶段数据预先确定。V1 更新的是当前信号并重新选择，不同时修改程序。V2、V3 中模型生成策略，数值评分、筛选执行和预算检查由相应工具完成。

V0、V1 保留同样的日志与历史接口，但其固定选择程序不消费策略修订建议。V2 开始使用反馈修改参数，属于该模块的定义，不额外扩大任务证据来源。

| 1 | V0＋预算匹配 Random | 阶段训练接续、信号刷新、外层状态机 | 建立静态与随机参照 |
| 2 | V1 动态评分 | Lopt 参数编辑、Leval 报告 | 动态更新是否值得 |
| 3 | V2 动态参数 | 程序结构编辑与合法性检查 | 自主调参是否有效 |
| 4 | V3 动态程序 | 控制轨迹整理、监督 mask、混合 SFT | 结构修改是否有效 |
| 5 | V4＋固定学生的选择能力验证 | 效率集成；General 数据、Base／Random | 控制学习是否进入最终方法 |

外部基线接口开发和小样本正确性检查可以从顺序1开始，避免正式阶段才发现工程障碍。大规模运行等待共同协议稳定。不同独立实验可以并行，同一闭环后续决策必须等待前轮结果。

## 5. 当前：NICE 验证

对应旧方案 E1；为 A5 提供初步证据，但不替代完整的策略候选评价比较。

继续完成高、中、低和随机子集的真实训练验证，随机组记录实际分值。除相关系数外，检查：

1. 高分子集是否有希望稳定超过随机。
2. 分技能估值是否可靠。
3. 来源、长度等是否解释主要差异。
4. 估值失败的案例和不确定性。
5. 样本评分、SFT、自由执行验证的实际成本。

样本侧监督梯度与目标任务自由执行产生的 NICE-derived 目标信号按实际实现分别记录，不能混写成普通开发 NLL 梯度。

若结果不足，先检查实现、目标定义和方差；必要时切换短期 SFT＋分技能任务验证。先确定一条主评价路线，不默认两条都跑完整主表。

**现在同步开发：固定策略执行器、统一 manifest、监督 token 装包、评分缓存；从现在开始完整保存控制反馈。**

## 6. V0：静态选择与 Random

Random 是基础对照，不是新增模块。明确其数据是提前确定还是逐轮抽取，二者不能混用同一结果。

V0 在初始模型下确定两个阶段的数据，保留共同质量、预算、去重和覆盖约束。按与动态配置相同的阶段和学习率协议训练，保存中间 checkpoint。

### 同评分直接选择对照

必须检查：相同 NICE-derived 分数及共同约束下，直接选择是否已经足够。

- 若 V0 就是这条直接排序路径，不另加重复行。
- 若 V0 采用复杂分支或其他选择目标，则单列一个共同约束下的直接排序对照。
- 不把它标成完整原版 NICE；明确为本项目单 checkpoint 派生对照。

当前 NICE 实验只有协议完全一致时可复用。已跑过不等于自动满足正式比较。

**运行期间准备：阶段接续、接受／拒绝、回退和当前信号刷新。拒绝路径可用测试配置检查，不等待真实退化。**

## 7. V1：动态评分、固定程序

新增：当前模型评分 → 固定程序选一批 → SFT → 根据当前已接受模型刷新 → 同一程序再次选择。

比较：

- V1 vs V0：阶段性重评分和重新选数的价值。
- V1 vs 预算匹配 Random：是否超过简单选择。

V1 不同时修改技能配比、阈值或 operator 结构。两次尝试使用相同任务训练预算及数据使用规则。

得到 M0、M1 后，同步启动小规模指标预测审计；不必等待完整方法。

**运行期间准备：Lopt 参数编辑、Leval 数值和语义证据报告。**

## 8. V2：开放参数修改

在 V1 基础上允许 Agent 根据反馈修改偏好区间、权重、技能配比等；结构固定。

比较 V2 vs V1，检验反馈式参数修订。此处变化包含将反馈用于策略修改，不能将结果进一步解释为某个单独参数的因果贡献。

保存每次提议、执行结果、反馈和实际选集。NICE 路线反馈高低分样本及技能语义特征；短期 SFT 路线反馈候选子集训练后的分技能表现。报告分清事实、代理估计与原因假设。

**运行期间准备：结构编辑、程序校验、候选最佳值和停止条件。**

## 9. V3：开放程序结构

进一步允许 operator 组合、顺序、分支修改。比较 V3 vs V2。

执行检查：

- 是否真正发生结构变化，而非只改阈值。
- 结构变化是否改变实际选集。
- 改顺序是否涉及截断、抽样、去重等顺序敏感操作；固定硬过滤未必顺序敏感。
- V2、V3 的信息和搜索资源是否一致。

若 V3 没有稳定改善，检查实现、方差、有效结构修改与搜索预算；确认无益时可删除结构自由度，不为故事强行保留。

选少量代表候选做真实训练核验，补充 A5。相同候选上的代理—实测比较与评价器改变后导致的搜索路径分叉，分开解释。

**运行期间准备：控制轨迹清理、目标 assistant mask、混合训练接口。**

## 10. V4：加入控制轨迹 SFT

控制学习是新增实验，连接旧方案 E5、A8。

从 V3 第一阶段训练前的共同 checkpoint 建立两条分支：

| 分支 | 任务数据和曝光 | 控制训练 |
| --- | --- | --- |
| O-task | 相同 | 无 |
| O-joint | 相同 | 加入通过检查的策略修订轨迹 |

先隔离控制训练的直接作用，再各自继续第二阶段，检验后续选择和闭环收益。控制 token 和额外成本单列。发现优势后，补等额外训练预算的任务数据对照，排除单纯训练量增加。

### 10.1 固定学生的控制器交叉实验

固定参考学生、候选池、报告、历史、评价工具与搜索预算，只替换 Lopt 权重；其他角色先不变。让控制器分别选数，再从共同参考学生训练并测收益。

不能控制器变了，学生、目标梯度和评价证据也一起变化。若要证明控制 SFT 的额外作用，优先比较任务训练后与联合训练后的控制器；与初始控制器的比较用于观察总体变化。

### 10.2 控制数据组织

以“当时可见策略＋反馈＋必要历史 → 有依据的下一步修订”为单位。工具返回作为上下文，选定 assistant 输出计算 SFT 损失。

失败策略可以放入历史上下文，不自动作为正向监督。事后外层结果不能提前放入早期输入。内层代理分数高不等于真实训练收益已确认。

若控制 SFT 无效，不强行进入最终方法。无论结果如何，任务提升本身都不能证明选择能力提升。

**运行期间准备：效率集成；General 数据、技能／约束接口及 Base、Random 小实验。**

## 11. 效率实验：不与 V0–V4 做笛卡尔积

### 11.1 小规模指标审计

从 V0／V1 的模型快照开始，用共同实测锚点预算比较：旧值不刷、平均变化、岭回归、小 MLP。固定审计 checkpoint 上的真实新指标可供各预测器复用。

关注准入错误、选集差异、边界跨越及预测误差。预测 NLL／entropy 变化不等于预测梯度；若最终不使用梯度近似，删除旧 A4 的对应内容。

### 11.2 最终下游比较

只保留：

1. 最终选择机制＋精确刷新。
2. 最终选择机制＋所选近似刷新。
3. 不刷新：有解释价值时补充。

不让每个预测器都跑完整闭环。近似方案改变选集后，模型路径分叉，必须真实训练，不能用公共路径日志模拟。

### 11.3 工程成本诊断

- 缓存开关：相同查询序列重放，核对输出一致，计时即可。
- 按需评分／全池建库：信号、决策一致时比较成本；查询预算改变实际搜索时补质量验证。
- 完整记录首次成本、刷新成本、缓存 I/O 和策略开销，不只报告稳定期速度。

预测值保留来源和版本，不当作实测真值。技能关注范围主要由稳定标签确定，避免陈旧阈值排除潜在候选。未关注数据允许保留旧值；重新关注时抽样校准。

**运行期间准备：冻结 Ours；外部基线协议和正确性检查；General 小规模闭环。**

## 12. 正式主表与基线

冻结评价器、operator 范围、控制训练、刷新方式、搜索上限、停止和验收规则后，开展正式运行。

外部方法沿用现有两份方案按任务适配；本文件不重新核定其发表信息。不同方法保留原生机制与合理选择频率，修改部分明确标 adapted。不能为了制造成本，强制所有静态方法每轮重算。

性能表与效率表复用同一运行记录。既比较相同任务训练曝光，也比较相同端到端资源；后者只有可比预算 checkpoint 才可直接复用。

早期配置与冻结版完全相同、日志完整且未根据最终测试调参时，可作为正式结果复用。否则保留为验证实验。重要对照补重复运行，报告全部预设运行而非最好一次。

## 13. 正式消融：只补核心去除项

| 对照 | 必要条件 | 是否额外运行 |
| --- | --- | --- |
| 完整方法 vs 固定结构、只调参数 | 结构修订是贡献 | 旧 V2 完全匹配则复用，否则补 |
| 完整方法 vs 无控制轨迹 SFT | 控制学习进入最终方法 | 旧 V3 完全匹配则复用，否则补 |
| 近似刷新 vs 精确刷新 | 声称刷新效率贡献 | 保留代表性真实训练比较 |
| 无跨轮历史 | 经验累积是主要解释 | 优先补充，不默认扩成多种记忆设计 |
| 单角色 vs 三角色 | 声称角色拆分带来收益 | 否则后置可选 |
| 有／无拒绝机制 | 出现实际拒绝且需要论证 | 首次拒绝处分支，其他条件不变 |

外层1／2／3次先从 checkpoint 提取自然增长曲线。等总训练量轮次对照只有在轮次数本身成为论点时再做。

## 14. 合并或删除原方案中的重复项

| 原项目 | 最新处理 |
| --- | --- |
| E2、E3、A7 | 主要由统一 V0–V3 承担，不分别建立多套训练矩阵 |
| A9 直接 NICE-derived 选择 | 与 V0 一致则合并；否则保留一个共同约束对照 |
| A1 缓存 | 查询重放、输出一致性和计时 |
| A2 按需／全池 | 优先成本诊断，只有决策改变才补训练 |
| A3 前向指标刷新 | 审计筛选预测器，再验证最终近似方案 |
| A4 跨轮梯度预测 | 不使用就删除 |
| A5 代理／真实评价 | 当前 NICE 验证＋少量同候选真实核验，非两套完整主表 |
| A6 轮次 | 自然曲线优先；不自动追加等预算矩阵 |

| A10 反馈／记忆／随机 recipe | 根据最终解释补有针对性对照，不预先全铺开 |

## 15. Coding 与 General 的分工

| 项目 | Coding | General |
| --- | --- | --- |
| V0–V4 递增链 | 主要机制场景 | 不完整复制 |
| 动态程序／参数对照 | 重点做 | 复验最重要差异 |
| 控制轨迹 SFT | 重点做 | 作为普适核心贡献时复验 |
| 精确／近似刷新 | 完整审计＋下游 | 最终方案代表性比较 |
| 角色、全部预测器、标签扰动 | 按需 | 通常不重复 |
| 外部性能和效率对手 | 必须 | 同样需要，不能自身消融替代 |

General 在 V4 阶段开始准备，效率阶段小规模验证，正式阶段展开主表。两域独立训练，尽量共享算法；任务接口差异明确记录。

## 16. 记录、复用与资源

每条运行保存配置版本、seed、模型和 adapter、数据 split、模板及 mask、程序与候选 manifest、实际选集、全部反馈、checkpoint、逐题评测和接受／拒绝。

分别记录输入 token、任务监督 token、控制监督 token、唯一数据 ID、累计曝光、评分并集、缓存命中及精确／陈旧／预测比例。
